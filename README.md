# نظام إدارة المجمّع السكني

تطبيق ويب لإدارة **مجمّع سكني واحد** — واجهة عربية RTL فقط، بالدينار العراقي.
العمود الفقري التشغيلي والمالي للمجمّع: المخزون العقاري · سجل الأشخاص · الدفتر المالي · العمليات.

> **الحالة:** قيد البناء. التنفيذ يتبع `docs/EXECUTION-ROADMAP.md` خطوةً خطوة.
> **لم تُتَّخذ أي قرارات عمل نيابةً عن صاحب المنتج.** ما يحتاج قراره مُجمَّع في `docs/OPEN-DECISIONS.md`.

---

## الأهداف التجارية (‏§1.2)

| # | الهدف |
|---|---|
| **O1** | استبدال متابعة الشقق والسكان والاشتراكات بالورق وExcel بمصدر حقيقة واحد |
| **O2** | معرفة أي شقة مباعة/فارغة/يسكنها مالك/مؤجّرة في أي لحظة — **لأن السكن يقود الفوترة** |
| **O3** | معرفة ما على كل صاحب عقد وما دفعه بالضبط، وإصدار فاتورة لكل دفعة |
| **O4** | إعطاء المالك تقارير مالية وإشغال حيّة وموثوقة **بلا أن يسأل الأدمن** |
| **O5** | تمكين الساكن من رؤية اشتراكاته ومستحقاته وفواتيره وسياراته وطلباته |
| **O6** | توجيه طلبات السكان وشكاواهم للقسم والموظف الصحيح ومتابعتها حتى الإغلاق |

## المبادئ الحاكمة (‏§1.3)

1. **لا يُخزَّن ما يمكن استنتاجه.** كل الإحصاءات استعلامات لا أعمدة. الاستثناءان المتعمَّدان فقط: `Account.balanceIqd` و`ApartmentResident.isActive`.
2. **حالة السكن هي مفتاح الفوترة.** `VACANT` = لا قيود دورية. كل تغيير سكن يُؤرَّخ.
3. **الدفتر يتبع العقد لا الشقة.** مالك أو مستأجر جديد لا يرث رصيد سابقه؛ الحساب القديم يُغلق ويبقى مقروءاً في تاريخ الشقة أبداً.
4. **المال عدد صحيح `BigInt` بالدينار.** لا `float`، ولا كسور، ولا وحدة فرعية. كل حقل مالي ينتهي بـ`Iqd`.
5. **كل حركة مالية مُدقَّقة.** مَن فعلها ومتى وما القيمة قبل وبعد.

## التشغيل

```bash
npm install
npm run dev
```

قبل أي أمر يمسّ قاعدة البيانات، انسخ `.env.example` إلى `.env` واملأ القيم.

### الأوامر

| الأمر | ما يفعله |
|---|---|
| `npm run dev` | خادم التطوير |
| `npm run build` | بناء الإنتاج |
| `npm run typecheck` | فحص الأنواع بلا إخراج |
| `npm run lint` | ESLint — يشمل حظر `ml-*`/`pl-*` وحظر `any` في كود المجال |
| `npm test` | اختبارات Vitest |
| `npm run db:validate` | التحقّق من `schema.prisma` بلا اتصال |
| `npm run db:migrate` | ترحيل التطوير (يستخدم `DIRECT_URL`) |
| `npm run seed` | بذرة البيانات |
| `npm run audit:money` | يرفض أي حقل مالي لا ينتهي بـ`Iqd` أو ليس `BigInt` |
| `npm run audit:completeness` | يتحقّق أنه لا فراغ في التغطية (انظر أدناه) |
| **`npm run verify`** | **كل ما سبق دفعةً واحدة** |

### تدقيق الاكتمال

`npm run audit:completeness` ليس زينة — هو ما يجعل «لا فراغات» **قابلاً للفحص آلياً** بدل أن يكون ادّعاءً. يؤكّد أن العدد الفعلي في الكود يطابق العدد الفعلي في المواصفة: 30 جدولاً · 33 enum · 39 قاعدة `R` مُسنَدة · 44 إجراءً · 9 مسارات · 12 تدفقاً · 12 قالب إخطار · 12 إحصاءً محسوباً · **23** صفّاً في مصفوفة الصلاحيات · وكل قيمة enum لها تسمية عربية بلا استثناء.

## قواعد لا تُخرَق

- كل مبلغ `BigInt` بالدينار، واسم حقله ينتهي بـ`Iqd`. لا `Float`، لا `Decimal`، لا `parseFloat`.
- `LedgerEntry` **append-only**: لا تعديل ولا حذف ولا `deletedAt`. الخطأ يُصحَّح بقيد معاكس.
- **دالة واحدة تكتب القيود:** `postEntry()` في `lib/ledger`. لا Server Action ولا cron ولا webhook يكتب `ledgerEntry.create` مباشرة.
- كل إعادة حساب للرصيد داخل **نفس معاملة** إدراج القيد، مع قفل صف على الحساب.
- كل مسار كتابة قابل لإعادة المحاولة **idempotent بقيد في قاعدة البيانات**، لا بفحص تطبيقي.
- الترخيص يُفرَض **داخل كل Server Action**، لا في layout أو proxy وحدهما.
- الواجهة RTL أولاً: خصائص CSS المنطقية فقط (`ms-*` · `me-*` · `ps-*` · `pe-*`). `ml-*`/`mr-*`/`pl-*`/`pr-*` **ممنوعة**.
- نصوص عربية · تواريخ ميلادية · `Asia/Baghdad` · **أرقام غربية**.
- ما لم يُوصف في المستندات الثلاثة **يُطرح سؤالاً، لا يُخترع**. الصمت فراغ لا إذن.
