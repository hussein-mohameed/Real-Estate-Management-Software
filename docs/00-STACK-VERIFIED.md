## 2. Next.js 16 — ثلاث حقائق تنقض نصّ المواصفة

كلها منقولة عن التوثيق المثبَّت في `node_modules/next/dist/docs/`، مع المسار.

### 2.1 🔴 `middleware.ts` **مهجور** — الاسم الصحيح `proxy.ts`

**المصدر:** `01-app/03-api-reference/03-file-conventions/middleware.md`

> «اصطلاح الملف `middleware.js` **مُهجَّر** في Next.js 16 وأُعيدت تسميته إلى `proxy.js`. كل الوظائف تبقى كما هي — الملف واسم التصدير فقط تغيّرا.»

**سجل الإصدارات في `proxy.md` سطر 774:** `v16.0.0 | Middleware is deprecated and renamed to Proxy. Proxy defaults to the Node.js runtime`

| | المواصفة §10.3 | الصحيح لهذا الإصدار |
|---|---|---|
| اسم الملف | `middleware.ts` | **`proxy.ts`** |
| اسم الدالة المصدَّرة | `middleware` | **`proxy`** |
| بيئة التشغيل | (غير مذكورة) | **Node.js افتراضياً**؛ و`runtime` في إعدادات المقطع **يرمي خطأ** إن ضُبط في ملف proxy |

### 2.2 🔴 التوثيق نفسه يحذّر من الاعتماد على Proxy في الترخيص

**المصدر:** نفس الملف، تنبيه في مقدّمته وقسم الترحيل (سطر 751):

> «‏Proxy يُستدعى منفصلاً عن كود العرض، وفي الحالات المُحسَّنة **يُنشر على CDN** للتعامل السريع مع التحويل — **لا ينبغي أن تعتمد على وحدات مشتركة أو متغيّرات عامة**.»
> «نوصي المستخدمين **بتجنّب الاعتماد على Middleware ما لم يوجد خيار آخر**.»

**الأثر على تصميمنا — وهو أثر أمني لا تجميلي:** الطبقة الأولى من «التحصين الطبقي» في §10.3 (‏proxy يمنع غير المصدَّق) **ليست حدّاً أمنياً** ولا يجوز أن تستعلم Prisma. دورها **تحويل رخيص بفحص وجود الكوكي فقط**. الحدّ الأمني الفعلي يبقى حيث تضعه المواصفة نفسها: `layout.tsx` لكل مجموعة، و**كل Server Action يعيد الفحص بنفسه**. هذا يقوّي قاعدة `0.10` ولا يضعفها.

### 2.3 🟠 `unstable_cache` استُبدل بـ`use cache`

**المصدر:** `01-app/03-api-reference/04-functions/unstable_cache.md`

> «هذه الواجهة **استُبدلت بـ`use cache`** في Next.js 16. نوصي بتفعيل Cache Components واستبدال `unstable_cache` بموجّه `use cache`.»

**الواجهة الصحيحة لمتطلّب §12.6** («كاش 5 دقائق لمؤشّرات المالك مع إبطال بالوسوم عند أحداث الدفع/القيد»):

| المطلوب في §12.6 | الواجهة في هذا الإصدار | المصدر |
|---|---|---|
| التخزين المؤقت | موجّه `use cache` | `01-directives/use-cache.md` |
| المدّة (5 دقائق) | `cacheLife()` | `04-functions/cacheLife.md` |
| الوسم | `cacheTag()` | `04-functions/cacheTag.md` |
| الإبطال عند الدفع/القيد | `revalidateTag()` | مذكورة في related الخاص بـ`use-cache.md` |
| التفعيل | `cacheComponents: true` في `next.config.ts` | `05-config/01-next-config-js/cacheComponents.md` |

**قيد لازم الانتباه له** (من `use-cache.md` حرفياً): «لاستعمال الكوكيز أو الترويسات، اقرأها **خارج** النطاق المُكاش ومرّرها كوسائط.» — مؤشّرات المالك على مستوى المجمّع كله لا على مستوى المستخدم، فهي قابلة للتخزين المؤقت بأمان بلا كوكيز.

### 2.4 ✅ مجموعات المسارات `(folderName)` — بلا تغيير

**المصدر:** `01-app/03-api-reference/03-file-conventions/route-groups.md` — «مجموعة المسارات تُنشأ بتغليف اسم المجلد بقوسين `(folderName)`… **ولا تُدرَج** في مسار الـURL.»

هيكل §9.1 (‏`(auth)` · `(owner)` · `(admin)` · `(staff)` · `(resident)`) **صالح كما هو**.

## 3. Prisma 7 — أربع حقائق تغيّر الخطوتين `0.3` و`0.4`

المصدر: مهارات Prisma الرسمية المثبَّتة مع الحزمة في `.agents/skills/prisma-upgrade-v7/`.

### 3.1 🔴 مولّد العميل تغيّر، والمخرَج **إلزامي**

```prisma
generator client {
  provider = "prisma-client"        // لا "prisma-client-js"
  output   = "../lib/generated/prisma"   // إلزامي، لم يعد له افتراضي
}
```

### 3.2 🔴 `datasource` **بلا `url`** — الاتصال انتقل إلى `prisma.config.ts`

الملف الذي يولّده `prisma init` في هذا الإصدار يحتوي `provider` فقط. الاتصال يُعرَّف في `prisma.config.ts` — **وموضعه لم يعد `schema.prisma` كما تفترض المواصفة.**

#### 🔴 وتوثيق Prisma المرفق **خاطئ** بشأن `directUrl`

مهارة Prisma الرسمية المثبَّتة مع الحزمة (`.agents/skills/prisma-upgrade-v7/references/prisma-config.md`) توثّق حرفياً:

```ts
datasource: { url: env('DATABASE_URL'), directUrl: env('DIRECT_DATABASE_URL') }
```

**والحزمة المثبَّتة لا تدعم `directUrl` إطلاقاً.** النوع في `node_modules/@prisma/config/dist/index.d.ts` سطر 26:

```ts
export declare type Datasource = { url?: string; shadowDatabaseUrl?: string; };
```

كُشف هذا بفشل بناء حقيقي لا بمراجعة نظرية:
`error TS2353: 'directUrl' does not exist in type '{ url?: string; shadowDatabaseUrl?: string; }'`

**درس يتجاوز هذه الحالة:** حتى توثيق المزوّد المرفق **مع** الحزمة قد يسبق الحزمة أو يتأخّر عنها. مصدر الحقيقة الوحيد هو **ملفات الأنواع المثبَّتة** — وهذا توسيع طبيعي لقاعدة `S9`.

#### الحلّ المُنفَّذ لفصل الاتصالين

هذا الملف يُقرأ من **الـCLI وحدها**؛ التطبيق يتصل عبر driver adapter. فالفصل يتحقّق بلا حاجة إلى `directUrl` أصلاً:

| الطرف | المتغيّر | لماذا |
|---|---|---|
| `prisma.config.ts` (‏CLI · migrate · studio) | **`DIRECT_URL`** | الترحيلات تحتاج اتصالاً مباشراً |
| `lib/prisma.ts` (التطبيق وقت التشغيل) | **`DATABASE_URL`** | التطبيق يعمل على المجمّع (pgbouncer) |

**وتُستخدم `process.env` مباشرةً بدل `env()`** لأن `env()` يرمي عند غياب المتغيّر فيمنع `prisma validate` من العمل بلا قاعدة بيانات — وهو فحص نريده متاحاً في CI وقبل توفّر أي اتصال. تحقّق فعلي: `prisma validate` ينجح الآن بلا `.env` إطلاقاً.

### 3.3 🔴 **driver adapter إلزامي** — لا محرّك ثنائي بعد الآن

> «‏Prisma v7 **يشترط** driver adapters لاتصالات قواعد SQL. هذا هو مسار تنفيذ SQL القياسي في إصدارات Prisma الحالية.» — `references/driver-adapters.md`

لذلك `@prisma/adapter-pg` و`pg` **ليستا اعتمادَين اختياريتين أضفتُهما**، بل شرط تشغيل للإصدار المثبَّت:

```ts
const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL })
const prisma  = new PrismaClient({ adapter })
```

### 3.4 🟠 تحميل متغيّرات البيئة صار صريحاً

`.env` **لا يُحمَّل تلقائياً** — `prisma.config.ts` يبدأ بـ`import 'dotenv/config'`. لهذا `dotenv` اعتماد تطويري.

## ⚠️ ‏Tailwind v4: `@theme` لا يعمل داخل `@media`

**العيب:** لوحة الوضع الليلي كانت مكتوبة هكذا:

```css
@media (prefers-color-scheme: dark) {
  @theme { --color-surface: oklch(0.20 …); }   /* ← خطأ */
}
```

‏Tailwind v4 يعالج `@theme` وقت البناء و**يرفعه خارج `@media`**. فتُصدَر قيم الليل على `:root` **بلا شرط**، وتكتب فوق قيم النهار. النتيجة: **التطبيق داكن دائماً**، ومستخدم الوضع الفاتح لا يراه أبداً.

**الصواب** — `@theme` يُصدِر متغيّرات على `:root`، فيكفي تجاوزها بقاعدة `:root` لاحقة:

```css
@theme { --color-surface: oklch(1 0 0); }

@media (prefers-color-scheme: dark) {
  :root { --color-surface: oklch(0.20 …); }
}
```

**لماذا يستحقّ التسجيل:** لم يفشل بناء ولا فحص أنواع ولا اختبار — الملف صالح والقيم صحيحة، والخطأ في **موضعها بعد التجميع**. ولا يظهر على جهاز مطوّر يعمل بالوضع الليلي أصلاً.

**كيف كُشف:** بقراءة CSS المولَّد في المتصفّح مع ضبط `prefers-color-scheme: light` — ظهر `--color-surface` معرَّفاً مرّتين وكلتاهما داكنة، والأبيض غائب من المخرَج تماماً.

**الحراسة:** ثلاثة اختبارات في `tests/unit/ui-rtl.test.ts` — لا `@theme` داخل أي `@media` · لوحة الليل تتجاوز عبر `:root` · كل رمز ليلي له مقابل نهاري. أُثبت فشلها الثلاثة على الكتابة المعطوبة.
